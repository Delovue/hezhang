## 使用与证据

安装 README 规定的 Python 3.12、Node.js 22.12+（22.x）或 24+、锁定依赖和 Chromium 后，在根目录执行：

```powershell
backend/.venv/Scripts/python.exe scripts/acceptance.py --directory .e2e/acceptance-new
```

Linux/macOS 使用 `backend/.venv/bin/python`。每次使用新目录，失败后查看 `summary.json` 指向的日志，修复后使用另一新目录重新运行。`automated_status` 只反映自动化；`manual_acceptance` 始终保持 `pending`。`environment.dirty` 为 true 时说明有未提交文件，不能把结果冒充为干净提交的验证。

CI 的 Artifacts 以平台和提交哈希命名。仅归档测试报告、覆盖率、浏览器失败截图／trace、重启结果；不上传数据库、`.env` 或整个演示目录。Artifacts 到期后，运行状态及仓库内经核对的摘要仍可追溯。

本次实际结果见 [系统验收报告](ACCEPTANCE_REPORT.md) 的 2026-11-01 补充记录。旧报告中的“前端尚未开发”“结算尚待集成”等描述属于当时模块分支，已被主分支的真实实现及整系统验收覆盖，不是当前功能缺口。

PR #7 后续 Windows 检查暴露了慢速认证和成员刷新时序问题，已统一认证与刷新等待辅助函数，新增 2 项受控延迟浏览器回归；本地全套浏览器从 17 项增至 19 项且全部通过。失败原因、trace 时间和修复后的远端检查入口见系统验收报告开头。
