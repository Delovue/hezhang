# 合账运行与课堂演示指南

本指南对应 `v1.0.0` 课堂演示前第一版，软件测试验收由角色丁统一完成。演示使用真实 Vue 页面、FastAPI 服务和独立 SQLite 数据库，主流程约 4 分 30 秒。全部账号及金额均为演示数据。

## 一 准备环境

安装 Git、Python 和 Node.js。项目后端使用 Python 3.12；前端支持 Node.js 22.12 以上的 22.x 或 24 以上版本。首次安装需要网络；依赖安装完成后，本地演示不依赖外部服务。

在仓库根目录执行：

```text
python -m pip install uv==0.13.6
cd backend
python -m uv python install 3.12
python -m uv sync --locked --managed-python
cd ../frontend
npm ci
cd ..
```

## 二 初始化并启动

Windows PowerShell，在仓库根目录执行：

```powershell
backend/.venv/Scripts/python.exe scripts/course.py prepare --directory .demo/lesson-01
backend/.venv/Scripts/python.exe scripts/course.py serve --directory .demo/lesson-01
```

macOS 或 Linux 将解释器路径改为 `backend/.venv/bin/python`，其余参数不变。页面地址为 http://127.0.0.1:15174，API 文档为 http://127.0.0.1:18001/docs。需要其他端口时使用 `--api-port` 和 `--web-port`，两者应不同且空闲。

`prepare` 创建新目录、随机 JWT 密钥、迁移后的数据库和样例；已有目录会被拒绝，不提供覆盖或清空选项。再次练习时改用 `.demo/lesson-02`。`serve` 使用已有目录，不重置费用；Ctrl+C 停止由该命令启动的两个服务。`.demo/`、数据库和 `.env` 都在 Git 忽略范围内，不能把真实数据当作演示数据分享。

| 会话 | 用户名 | 显示名 | 演示密码 |
| --- | --- | --- | --- |
| A | demo_a | 小王，活动创建者 | Demo-pass-2026 |
| B | demo_b | 小李 | Demo-pass-2026 |
| C | demo_c | 小陈 | Demo-pass-2026 |

可用三个独立浏览器窗口或配置文件；也可用三个标签页分别登录，因为令牌保存在各页面内存中。刷新后需要重新登录。讲解前准备好三个会话并打开同一个“三人出游 · 现场演示”活动。该活动已有三名成员，预算 200 元，尚无费用。

“分摊方式样例”活动包含 100 元指定金额分摊（20、30、50）和 600 元按份数分摊（2∶1∶1，对应 300、150、150），可在问答时展示，不改动主流程数字。

## 三 3–5 分钟现场流程

| 时间 | 页面与操作 | 核对与讲解 |
| --- | --- | --- |
| 0:00–0:30 | A 打开活动概览与成员 | 三人旅行共同记账，预算 200 元；说明每人有独立账号 |
| 0:30–1:10 | A 在费用明细新增“午餐”，120 元，垫付人 A，三人均摊，预览后保存 | 每人承担 40 元，预览与保存使用同一算法 |
| 1:10–1:40 | B 新增“车费”，60 元，分类交通，垫付人 B，取消勾选 C，保存 | 只有 A、B 各承担 30 元 |
| 1:40–2:10 | A 刷新，打开结算与付款 | 消费 180 元；A 应收 50，B 应付 10，C 应付 40 |
| 2:10–2:30 | A 点击“封账并开始结算”并确认 | 费用与成员冻结，防止结算时账目变化 |
| 2:30–3:00 | C 刷新并登记向 A 已付 20 元；A 刷新后确认收到 | 登记时余额不变；确认后应收应付变为 30／10／20 |
| 3:00–3:40 | C 再登记 20 元，B 登记 10 元；A 刷新确认两笔 | 所有余额归零，活动自动变为已结清 |
| 3:40–4:10 | A 归档，打开操作历史并导出 CSV | 历史可看操作人和变化，消费总额仍为 180 元 |
| 4:10–4:30 | 打开分摊或付款服务的代码 | 说明输入、计算／权限、事务与测试位置 |

付款按钮表示登记与核对已发生的外部付款，演示中只使用虚构样例，不执行真实转账。切换会话后点击“刷新”获取其他成员最新操作。不要在主流程中插入其他金额，否则预期余额会改变。

## 四 常见答辩问题

| 问题 | 说明与代码入口 |
| --- | --- |
| 100 元三人均摊为何多出一分钱？ | 整数商为 3333 分，余下 1 分按成员 ID 分配；`domain/split.py::split_equal` |
| 为什么付款登记后余额不变？ | PENDING 只占用额度，CONFIRMED 才参与余额汇总；`domain/balance.py` |
| 管理员能否替别人确认？ | 本项目没有平台管理员；创建者也不能替其他收款人确认；`domain/payment.py` |
| 两个人同时请求会怎样？ | 读额度前取得 SQLite 写锁；请求编号唯一、状态条件和事务共同避免重复或超额；`database.py`、`services/payment.py` |
| 同一费用被两个窗口修改？ | version 不一致返回 409，页面保留草稿、加载最新版本后再由用户保存；`services/expense.py`、`ExpenseEditor.vue` |
| 删除费用能追溯吗？ | 逻辑删除，审计保留前后内容，有效消费汇总过滤已删除记录 |
| 建议是不是最少转账次数？ | 是确定的贪心匹配，保证额度正确，不宣称全局最优 |

## 五 重现测试

在仓库根目录运行真实 HTTP 与重启验证（目录必须是新的）：

```powershell
backend/.venv/Scripts/python.exe scripts/course.py verify --directory .e2e/rehearsal-01
```

它创建自己的临时账本、启动 API、完成 18 项流程检查、停止并重启服务、核对 3 项持久化结果，最后停止自己启动的服务。结果保存在目标目录的 `verification.json`。不要将这条验证命令用于正式演示目录。

完整测试命令见 [系统验收报告](ACCEPTANCE_REPORT.md)。验证用的 18000、15173 端口与正常演示用的 18001、15174 分离；端口被占用时先核对占用进程，不要结束不属于本项目的程序。
