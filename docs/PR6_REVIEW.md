## 发现与修复

| 问题 | 修复及回归证据 |
| --- | --- |
| 转账建议称“几笔即可结清”，但待确认付款尚未抵扣余额；全部登记后仍可能没有结清 | 改为“几笔建议”，区分可继续登记、全部待确认和已经结清；真实三账号浏览器流程断言部分待确认、全部待确认、确认后结清三种状态 |
| 自定义分类 `constructor`、`__proto__`、`toString` 被误当成内置分类，生成无效配色类名 | 只读取分类表自身属性；先复现测试失败，再验证三个名称均返回有效配色 |
| 日期分组只累计当前加载记录，分页时容易被理解为当日总额 | 明确标为“已加载小计”；真实 API 创建同日 21 笔费用，验证首屏 20 笔为 0.20 元、加载后为 0.21 元且仍只有一个日期分组 |

同时验证“我参与的／我垫付的／全部”快速筛选：成员仅参与两笔、未垫付任何费用时，列表分别为 2、0、3 笔。检查了默认费用标签、生命周期入口、权限按钮、成员重名标识以及桌面／390px 手机截图。后端费用接口本身按日期降序排序，符合日期分组函数的输入约定。
